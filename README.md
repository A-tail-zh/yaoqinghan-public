# 通用邀请函系统

手机邀请函、内容管理后台与 MySQL 回执服务。默认使用通用文字和 CSS 占位界面，不附带客户品牌、活动原稿、地图截图、音乐或第三方字体。

| 目录 | 内容 |
| --- | --- |
| [src/](src/) | H5 前台，包含页面、动画、样式和后端接入 |
| [admin/](admin/) | Vue 3 + Element Plus 内容发布、素材上传和回执查询 |
| [server/](server/) | Express API、登录会话、MySQL 迁移及测试 |

## 已实现功能

| 模块 | 功能与代码入口 |
| --- | --- |
| H5 展示 | [邀请函页面](src/App.vue) 包含左右开门、火漆、绿金背景、文字入场、翻页、地点图片铺满、表单自动填充样式和成功弹窗。展示页及文案由后台配置驱动。 |
| H5 接口 | [公开接口调用](src/invitation.ts) 支持配置读取、回执提交、请求超时和重复提交键。页面在真实保存成功后显示确认，到期后关闭活动内容。 |
| 管理后台 | [管理页面](admin/src/App.vue) 支持登录、草稿编辑发布、图片及 BGM 上传、追加展示页，以及回执筛选、人数合计、分页和静默自动刷新。 |
| 后端服务 | [服务入口](server/index.js) 集成 MySQL、会话权限、草稿版本校验、发布快照、素材校验、回执并发去重和一年到期控制。 |

前台、管理后台与后端在同一个仓库维护。新数据库使用通用草稿，管理员编辑并发布后可访问 H5。背景、封面、地点和音乐均通过后台按需配置，不依赖本地设计文件。

## 本地开发

使用 Node.js 22 和 MySQL 8。服务端配置参照 `server/.env.example`，实际配置和登录凭据由本机保管。

```powershell
# API 与已构建的管理后台
cd server
npm ci
npm run migrate
npm start

# 管理后台，另开终端
cd admin
npm ci
npm run dev

# H5，在项目根目录另开终端
npm ci
npm run dev -- --port 5188
```

API 地址为 `http://127.0.0.1:3080`，管理后台开发地址为 `http://127.0.0.1:5189/admin/`。完整接口、数据库初始化、素材上传和部署说明见 [服务端说明](server/README.md)。

## 验证

```powershell
npm run build
npm --prefix admin run build
npm --prefix server test
# 配置独立 invitation_h5_test 数据库与 server/.env.test 后
npm --prefix server run test:integration
```

移动端页面回归需安装 Python Playwright 和 Microsoft Edge。构建 H5 并启动预览后，运行 `python tests/h5-mobile.py http://127.0.0.1:5188/`，检查手机满宽、视口缩小、行内校验及提交失败后的重试。该测试模拟 API 响应，不读取活动内容或写入真实回执。

## Git 约定

| 分支 | 用途 |
| --- | --- |
| `main` | 保存前台、管理后台和后端一起验证通过的稳定版本。合入后保持工作区干净。 |
| `develop` | 汇总功能改动并进行前后端联调。当前已与 `main` 同步。 |
| `feat/<功能名>`、`fix/<问题名>`、`docs/<主题>` | 从 `develop` 创建短期分支。一个业务功能涉及前后端时，在同一功能分支内完成配套修改，按模块分别提交。 |

功能分支完成后合入 `develop`，执行前台构建、后台构建和相关后端测试，再将验证后的版本合入 `main`。合并完成的短期分支及时清理。多个会话共用一个工作目录时，应协调分支切换和文件修改，避免彼此覆盖。

提交说明使用清晰的功能名称，并在正文说明行为、影响范围和验证结果。提交按数据库与登录、内容发布、素材上传、回执与统计、API 集成、H5 前台、管理后台和文档区分功能。

新克隆请配置自己的提交身份，建议使用 GitHub 隐私邮箱。

```powershell
git config --local user.name "你的 GitHub 用户名"
git config --local user.email "你的 GitHub 隐私邮箱"
```

依赖包、构建输出、本机配置、登录凭据、运行日志、测试截图及上传媒体由 `.gitignore` 排除。原活动图片、参考视频、PSD 设计原稿及专用导入工具仅在本地保留，不提交。数据库业务记录与媒体目录需单独备份。仓库只保存通用源码、迁移结构、测试和依赖锁文件。默认界面通过 CSS 和系统字体渲染，不需要打包设计素材。

真实密码、访问令牌、会话密钥和证书私钥只保存在本机配置或 `secrets/` 中；本机部署记录放在 `.local/` 或 `.runtime/`，数据库备份和回执导出分别放在 `backups/`、`exports/`。这些路径不提交，示例配置仅使用占位值。不要将真实姓名、电话、回执记录写入源码、测试样例或提交说明。

每次提交前检查暂存文件和差异，确认没有夹带私密资料；不要使用 `git add -f` 强制加入上述文件。忽略规则不会保护已经跟踪的文件，若发现密钥已上传，应先作废或更换密钥，再清理提交历史。本地私密资料的备份与 Git 仓库分开保管。

## 素材与公开版本

图片、视频、音乐、字体和地图数据的授权独立于系统代码。使用者上传前需自行确认使用与传播权限，不能以删除品牌文字代替素材授权。依赖包遵循各自许可证。

公开版本从干净历史开始，按模块整理提交；旧活动原稿与旧历史仅作本地私密备份。不要合并旧历史或执行 `git push --mirror`，避免将已排除内容重新推送。已有活动的数据库和 `MEDIA_DIR` 保持独立，代码更新不会自动清空或替换它们。

重写分支不会立即清除托管平台保存的旧提交对象。将原有仓库改为公开前，应确认旧提交链接不能继续读取已排除素材；仍可读取时保持私有，先完成平台清理，或向全新仓库仅推送通用版本的分支。
